
## 已知坑：换行显示模式下连续缩进的折行行为

独立页的“换行显示”开关只是把 `textarea` 的 `wrap` 从 `off` 切到 `soft`，不改写 `value`。
但 `wrap="soft"` 默认按 `white-space: pre-wrap` 排版，会把折行边界处的前导空格“悬挂”在行尾（算字符、不占行宽、不触发折行），
而无空格长串（如 `7777…`、长 URL）又没有字符级断点。结果是持续缩进时：整段文字一次性跳到下一行，落下后静止几拍，再继续向右退；
正确表现应是以 `12345` 为例，`5` 先单独掉到下一行，再缩进 `4` 跟着下来，字符逐个从行尾剥离，全程无停顿。

修复只在 `#standalone-workspace-theme` 样式块内，两条属性缺一不可：

- `white-space: break-spaces` —— 空格不悬挂、每个空格后都是合法断点（治“落下后停顿”）；
- `word-break: break-all` / `overflow-wrap: anywhere` —— 长串可在任意字符处断开（治“整段一次性跳行”）。

规则用 `textarea[wrap="soft"]` 精确绑定，`wrap="off"` 时恢复 `white-space: pre`，横向滚动行为不变。
不要用 JS 测量字符宽度、插入换行符或模拟折行；不要改动共享运行时的缩进算法、选区映射、统计与导出逻辑。
验收时务必用“无空格长串 + 持续缩进”测试，普通带空格文本暴露不出此问题。
